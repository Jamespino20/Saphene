### [MINOR][bug] Relative base path risk in multi-page build configuration
- **Reviewer:** Maintainability Reviewer
- **Location:** `site\vite.config.ts:6`
- **Evidence:**
```
base: "./",
```
- **Long-term impact if unresolved:** Using a relative base path ('./') in a multi-page Vite application causes asset URLs in generated HTML files and bundled JS chunks to resolve relative to the current browser location. If entry points like 'docs.html' or future nested routes are served from subpaths (e.g., '/docs/'), asset requests will fail with 404 errors in production. As the application grows to include additional entry points or client-side routing, asset loading will break unpredictably depending on hosting environment URL rewrites.
- **Questions for the developer:**
  - Is this site required to support deployment to arbitrary relative subpaths, or will it be hosted at a fixed domain root/subpath?
  - Will 'docs.html' be served at root level alongside 'index.html', or via a subpath route like '/docs'?
- **Fix direction:** Replace 'base: "./"' with an absolute root path '/' or configure it dynamically via an environment variable (e.g., process.env.VITE_BASE_PATH || '/') to guarantee deterministic asset resolution across all pages.
