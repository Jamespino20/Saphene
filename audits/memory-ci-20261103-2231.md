### [MAJOR][bug] Destructive clean step executes before validating source directory existence
- **Reviewer:** Maintainability Reviewer
- **Location:** `scripts\copy-site-dist.mjs:3`
- **Evidence:**
```
await rm("dist", { recursive: true, force: true });
```
- **Long-term impact if unresolved:** If the site build step fails or is skipped prior to running this script, the destructive 'rm' empties the target 'dist' directory before discovering that 'site/dist' does not exist. This leaves the build output in a corrupted state and prevents recovery strategies that rely on previous valid artifacts.
- **Questions for the developer:**

### [MINOR][performance] Redundant directory creation call prior to recursive copy
- **Reviewer:** Performance Engineer
- **Location:** `scripts\copy-site-dist.mjs:4`
- **Evidence:**
```
await mkdir("dist", { recursive: true });
```
- **Long-term impact if unresolved:** Node.js 'fs.promises.cp' automatically creates target destination paths when '{ recursive: true }' is enabled. Calling 'mkdir' explicitly right after deleting the directory creates unnecessary disk I/O operations that degrade execution performance on high-latency or containerized filesystems.
- **Questions for the developer:**
  - Are all deployment environments targeting Node.js >= 16.7.0 where 'cp' handles recursive destination creation?
  - Is there a requirement to ensure permissions on 'dist' before copying contents?
- **Fix direction:** Remove 'await mkdir("dist", { recursive: true });' and allow 'await cp(...)' to handle target directory creation directly.
**Surrounding code (scripts\copy-site-dist.mjs, lines 1–6):**
