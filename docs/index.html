Why

Built-in AI and coding agents (Cline, Kilo, Cursor, OpenCode) can check a claim when asked — interactively, once, with no receipts. None of them persist what was verified, re-check it when the disk changes, or fail a PR when your notes start lying. Saphene is the audit layer those tools don't have.

Four commands

# scaffold a memory directory (or point at an existing one)
npm run init -- --memory-dir ./memory

# verify claims in one file
npm run bridge -- claims.md --repo ../your-repo

# audit a whole memory directory against a repo, ledger + drift diff
npm run memory -- --memory-dir ./memory --repo ../your-repo

# audit against implementation code only — specs can't testify for themselves
npm run bridge -- claims.md --repo ../your-repo --code-only

# code + business-flow audit: model finds the rot, ledger remembers it
npm run audit -- --repo ../your-repo --update-ledger

Case study: auditing a failed project

Agapay — a multi-tenant microfinance SaaS, dormant since May 2026. Its README promises a Compassion Policy, vouching, KYC, trust scores. We asked Saphene one question: which promises did the code keep?

matched → prisma/init.sql:86: CREATE TYPE "CompassionActionType" AS ENUM ('grace_period', 'term_extension', 'penalty_freeze');
partial → src/app/api/loans/apply/route.ts:51: // THE NEXT STEP would be implementing a Bearer Token (JWT) extractor here.

The second receipt is the point: Saphene matched a TODO comment saying the feature isn't implemented yet — and showed its work so a human catches it in two seconds. Precision is a journey; the receipts make it auditable.

Saphene Review — drift fails the PR

Commit a baseline ledger like a lockfile. Every pull request re-verifies claims against the PR tree and comments with the delta:

### ⚠ Drift detected — this PR breaks 1 verified claim(s)

Speaks MCP. Sits in CI.

Agent plugin via MCP

One stdio server covers VS Code Copilot agent mode, Cursor, Cline, and OpenCode: saphene_bridge, saphene_memory, saphene_verify. Agents stop guessing; they call the ledger.

GitHub Action

Clones your target repos on every push, verifies claims, posts the verdict table to the job summary. Fails on drift. See it green →

Model-backed extraction

Any OpenAI-compatible endpoint. Retry with backoff, fallback model chain, heuristic mode when no key is present. Your memory becomes structured claims; the evidence loop stays deterministic.

Code & business-flow audit

The model hunts bugs, security holes, and dead-end workflows; every finding's quote is re-verified by grep before it's believed, then ledgered — so re-audits diff code rot across commits.
