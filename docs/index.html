The Loop — why developers keep it running

One audit is a snapshot. The ledger turns it into a cycle: fix, verify, re-audit. Every change to your code's health is diffed against the last run. Click a step.

1

Audit — the panel files its review

Four reviewer personas (security, performance, business-flow, maintainability) examine the code in parallel. Every finding must quote the file verbatim — and the quote is re-verified by grep before the finding is believed. Findings land in a ledger with stable IDs.

$ npm run audit -- --repo . --update-ledger
2

Fix — prompts an agent can actually run

The markdown report gives every finding surrounding code, long-term impact, and the reviewer's open questions. Paste the fix prompt into Copilot, Cursor, Cline, or OpenCode — if a question changes the approach, the agent is instructed to ask you first.

npm run audit -- --repo . --report my-fixes.md
3

Verify — the patch can't silently break promises

After the fix, the claim ledger re-checks documented behavior against the new code, and the PR gate diffs verdicts against the committed baseline. A patch that makes a documented claim false fails the pull request — with the citation that proves it.

$ npm run review -- --claims srs.md --repo . --ledger .saphene/srs.ledger.json
4

Re-audit — rot becomes a diff

The next audit diffs against the ledger: fixed findings show as resolved, newly introduced ones as new, and previously-verified claims that stopped holding as drift. Code health stops being a vibe and becomes a changelog.

vs previous audit: 41 unchanged, 3 fixed, 2 new, 1 regressed
5

Forget about it — CI runs the loop for you

Two GitHub Actions ship in the repo: one verifies claims on every push and posts the verdict table, the other comments on every pull request with its drift delta. Add a cron trigger and the nightly audit watches the repo while you sleep.

on: push: [main] pull_request: schedule: [{cron: "0 3 * * *"}]

Adopt a legacy repo on day one

New job, inherited codebase? Audit it before you touch anything. The panel maps where the bodies are buried, and the ledger becomes your baseline for the only question that matters: is my refactor making it better?

Stop documentation rot

Point claims at your README, ADRs, and wiki. When the code stops matching the docs, CI flags the exact line that lied, before your teammates read it.

Nightly repo watch

Cron the audit action at 3 AM. Wake up to a diff of what changed in your code's health, not a wall of repeats: stable IDs mean only real changes surface.

Capstone & SRS traceability

ISO/IEC/IEEE 29148-aligned: requirements become claims, evidence becomes citations, and the traceability matrix exports to CSV or markdown for your defense panel.

Post-upgrade regression watch

Major version bumps silently break behavior. Commit a claims baseline and the PR gate tells you exactly which documented behaviors the upgrade broke.

Agent memory hygiene

Over MCP, your coding agent checks its own memory before answering. This note says X, the disk says Y. Saphene is the tool agents call instead of guessing.

Speaks MCP

Lives in CI

The public run clones target repos on every push, verifies claims, and posts verdict tables to the job summary. Fails on drift.
